# Khatet Project Overview

## Purpose

Khatet is a collaborative web platform for student teams to plan projects, organize work, and keep project discussion in one shared workspace. Teams often split tasks, deadlines, files, and decisions between chat applications, spreadsheets, and separate documents, which makes ownership and progress difficult to follow.

The source of truth for scope, priorities, and sprint plans is the team's Sprint 0 report (SWE 444). This overview summarises it for contributors.

## First release scope

- Passwordless sign-in with a 6-digit email code, and a unique username for every user.
- Projects: create, list, open, rename, and delete (owner only).
- Invitations: the owner invites a registered user by username; the invitee accepts or declines from their notifications.
- Members: everyone sees the member list; the owner sets task access and removes members; a Team Member can leave a project.
- Tasks with a required title and at least one assignee, plus optional description, priority, due date, and phase. A new task starts in To Do.
- Task workflow: Backlog, To Do, In Progress, Ready for Review, Done. Blocked is a flag on an In Progress task, with an optional reason.
- Kanban board with filter (assignee, status, priority) and search by title.
- Task activity history, phases on a timeline, project overview, notifications, and project chat with task references.
- AI project report generated by the owner and readable by every participant.
- Could have: automatic AI reports (Weekly, Monthly, or Disabled) and CSV task import.

## Roles and access

The Project Owner has full project control, including membership and task access. The owner cannot leave their own project.

Each Team Member has one task-access level, set by the owner:

| Level | What the member can do with tasks |
| --- | --- |
| View tasks only | View tasks. Cannot create, edit, or move tasks. |
| Edit assigned tasks (default on joining) | Edit and move only the tasks assigned to them. |
| Edit all tasks | Create, edit, move, and delete any task. |

At every level, a member can view the project and use project chat. The backend enforces these rules; the interface only explains them.

## AI project report

The report shows a summary of progress, warnings (such as overloaded members, unrealistic deadlines, or long-blocked tasks), and suggestions, with the date it was generated. The backend sends a limited project summary to the AI service (Claude API or OpenAI API, chosen by 28 October 2026) and stores the result. The report never creates, edits, assigns, or moves anything.

## Out of scope

- Native iOS or Android apps. Khatet is used through the mobile browser.
- Sign-in with passwords or with Google, Microsoft, or other social accounts.
- File uploads and attachments in tasks or chat, voice and video calls, and direct messages between two users.
- Integrations with outside tools such as Google Calendar, Slack, GitHub issues, or Trello.
- Payments, subscriptions, or paid plans for end users.
- Arabic interface and right-to-left layout. The first release is in English only.
- AI that changes tasks, assigns work, estimates durations, or acts as a chatbot.
- A purchased domain, paid hosting, and real user data beyond the course period.

## Technology direction

| Area | Direction |
| --- | --- |
| Web app | React, JavaScript, Vite, React Router, TanStack Query, React Hook Form, Zod, dnd-kit; hosted on Vercel |
| Styling | Tailwind CSS with the shared Khatet tokens |
| API | Node.js and Express, REST documented with OpenAPI; hosted on Render |
| Data | PostgreSQL on Supabase, with Prisma migrations |
| Authentication | Supabase Auth email one-time code, sent through Gmail SMTP |
| Project chat | Refresh every few seconds first, then Socket.IO on the Express backend |
| AI | Claude API or OpenAI API, key stored only as a hosting secret, 10 USD spending limit |
| Testing | Vitest, React Testing Library, Supertest, Playwright, Lighthouse |
| CI | GitHub Actions on every pull request (lint, tests, build, migration checks); a failing check blocks the merge |
| Monitoring | UptimeRobot on the health check every 5 minutes |
| Local development | No local database; each developer uses their own free Supabase project |

All services use free plans; only the AI credit costs money. Record an agreed change in the Sprint 0 report and the relevant documentation before implementation diverges.

## Repository status

The web app (`apps/web`) has the Sprint 1 screens running on an in-memory sample API. The backend, database, example settings file, and automated checks are added during Sprint 1 (TF-01 to TF-11). Test notes go in `docs/testing` and training notes in `docs/training`.

## Working agreement

1. Start each change from the default branch.
2. Use a short branch for one focused task.
3. Open a pull request; merge into the protected main branch only after at least one review and passing checks.
4. Write tests in the same pull request as the code.
5. Keep product scope and API changes documented.
6. Never commit secrets, credentials, or local environment files.
